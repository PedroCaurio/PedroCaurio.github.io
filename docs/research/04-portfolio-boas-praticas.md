# Portfólio — o que recrutadores procuram (nov/2026)

## Conclusão

Recrutadores escaneiam um portfólio em **~15 segundos**. Um portfólio é um **argumento curado**, não um museu de tudo que você já digitou. Poucos projetos (2–4 técnicos + jogos), cada um como **estudo de caso curto**, valem mais que uma lista de repositórios.

## Checklist "acima da dobra" (primeiros 5 segundos)

- Nome, papel desejado, frase de posicionamento, link para o melhor projeto.
- CTAs óbvios: **Baixar CV (PDF)**, GitHub, LinkedIn, e-mail clicável.
- Nunca só formulário de contato.

## Estudo de caso: os 5 elementos

1. **Problema** — o que estava quebrado/lento/faltando e para quem. Linguagem que alguém fora da área entende.
2. **Restrições** — prazo, equipe, hardware, legado. "Por que isso não era trivial?" Sem restrições, toda solução parece óbvia.
3. **Decisão e trade-off** — opções consideradas, a escolhida e o custo. É a parte mais ignorada e a que o hiring manager mais procura.
4. **Resultado** — com número quando houver (tempo, custo, taxa de erro, horas economizadas). Sem número: o que alguém passou a conseguir fazer.
5. **Seu papel** — o que você fez, separado do que o time fez. Preciso, não modesto nem inflado.

Tamanho: 300–600 palavras por projeto. Diagrama de arquitetura (Mermaid) ajuda muito.

Formato alternativo curto: **PARC** — Problem, Approach, Result, Code (link direto para o trecho de código que prova).

## Como escolher os projetos

- **Um de profundidade**: problema técnico difícil explicado em detalhe.
- **Um de escopo**: algo maior que você, onde seu papel foi arquitetura/coordenação.
- **Um recente**: últimos 2–3 anos, mostra o que você faz hoje.
- Filtro: projetos sobre os quais você falaria 20 min numa entrevista sem notas.
- Cortar sem dó: um projeto fraco puxa a média para baixo.

## O que diferencia em 2026

Evidência de cinco coisas: **resolução de problemas**, **julgamento técnico**, **qualidade de engenharia** (testes, segurança, performance), **letramento em IA** (como usa, avalia e integra IA de forma responsável) e **impacto**.

> Para o Pedro, "letramento em IA" é o diferencial principal: arquitetura de agentes, spec-driven, harness, MCP. O próprio site deve ser **prova viva** disso (construído com SDD + agentes, com o processo documentado numa página "Como este site foi feito").

## Checklist final

- Links ao vivo em todo projeto (demo, itch.io, repo).
- Rápido e bom no celular (recrutador abre no ônibus).
- CV e contato óbvios.
- Zero link quebrado ou lorem ipsum.
- Acessível: contraste, `alt`, navegação por teclado.
- Créditos corretos em trabalhos de equipe.

## Implicação para os repositórios do GitHub

Antes do lançamento, os repositórios que forem destaque precisam de README com: descrição, GIF/screenshot, como rodar, arquitetura, papel do Pedro. Vários repos hoje não têm README (ver [inventário](../context/inventario-github.md)).
