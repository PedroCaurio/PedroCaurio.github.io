# Portfólio de Game Dev — boas práticas (nov/2026)

## Conclusão

**Movimento vende jogo.** Cada jogo precisa de um loop curto de gameplay (3–5 s), papel exato, engine, tamanho do time e link jogável. Jogos de **game jam contam como portfólio legítimo**: provam que você escopa, constrói e entrega sob restrição.

## Por projeto

- Capa/loop animado (MP4/WebM mudo em loop; GIF só se < 3 MB).
- Resumo de uma linha + gênero.
- **Seu papel** (ex.: "Programação de gameplay e sistemas de upgrade").
- Engine e linguagem (Unity/C#, Godot/GDScript, Pyxel/Python, LÖVE/Lua).
- Tamanho do time e prazo; nome da jam, tema e resultado (só como a jam reportou).
- Créditos de **todos** os colaboradores com papel. Página que credita só uma pessoa num projeto de equipe é sinal de alerta.
- Link jogável (itch.io; browser build é o ideal) + repositório quando houver.
- Post-mortem curto: o que deu certo, o que deu errado, o que faria diferente; um bug ou mecânica interessante.

Estrutura para design: **Problema → Objetivo de design → Protótipo → Iteração → Resultado**.

## Layout recomendado

"Grade de thumbnails animadas" (melhor para generalistas/designers): grade de loops curtos, cada um abrindo uma página de estudo de caso. Cuidado com peso — usar vídeo comprimido e `loading="lazy"`.

## Seção de skills

Engines, linguagens e ferramentas separadas. O Pedro já tem: Unity, Godot, LÖVE 2D, Pyxel; C#, Python, Lua, C/C++, GDScript.

## RPG de mesa como ativo de portfólio

Não é comum, então diferencia — se apresentado como **design de sistemas**:

- Sistemas de RPG desenvolvidos → design de regras, balanceamento, economia, documentação técnica (game design puro).
- 7+ anos como mestre → narrativa, facilitação de grupo, improvisação, gestão de pessoas.
- Formato sugerido: uma seção "Sistemas & Mesa" com 1–2 sistemas próprios (PDF/página de regras, mecânica central explicada, playtests).
